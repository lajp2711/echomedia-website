# EchoMedia.ai Post-Refactor Validation

Use this checklist after the component refactor in #44 and before the next visible product/content sprint.

## Scope

The refactor split the site into focused React components and a shared content module:

- `src/App.jsx`
- `src/content/siteContent.js`
- `src/components/Button.jsx`
- `src/components/Header.jsx`
- `src/components/Hero.jsx`
- `src/components/OpsHelmProof.jsx`
- `src/components/Services.jsx`
- `src/components/Roadmap.jsx`
- `src/components/VanessaVision.jsx`
- `src/components/ContactCta.jsx`
- `src/components/Footer.jsx`

## Required command validation

Run from the repository root:

```bash
npm ci
npm run lint
npm run build
npm run preview
```

Expected result:

- `npm ci` installs from `package-lock.json` without dependency drift.
- `npm run lint` exits cleanly.
- `npm run build` emits a production `dist` bundle.
- `npm run preview` serves the production build for manual review.

## Manual review

Open the preview URL and check:

- Header logo, nav links, and Book a Call CTA render.
- Skip link appears when tabbing from the top of the page.
- Hero image renders and section copy is intact.
- OpsHelm proof cards render from `siteContent.js`.
- Services section shows EchoMedia.ai, Casakey LLC, and EchoAlpha.
- Roadmap steps render with icons.
- Vanessa COO section image, signature text, and freedom pillars render.
- Contact CTA mailto opens with the expected subject.
- Footer website and email links are keyboard reachable.
- Desktop and mobile layouts do not overflow horizontally.

## Accessibility targets

- Keyboard users can reach every link and CTA.
- Visible focus outline appears on links and buttons.
- Reduced-motion preference minimizes transitions and smooth scrolling.
- Lighthouse accessibility score target: 95+.

## Performance targets

- Lighthouse mobile performance target: 90+, unless a lower score is documented with the cause.
- No large unoptimized media regressions.
- Production bundle is generated by Vite without warnings requiring immediate action.

## GitHub Actions

The workflow `.github/workflows/github-pages.yml` is configured to run on pushes to `master` and manual dispatch. It performs:

1. `npm ci`
2. `npm run lint`
3. `npm run build`
4. GitHub Pages artifact upload and deploy

If no workflow run is visible for the latest commit, trigger `workflow_dispatch` from GitHub Actions or push a small documentation-only commit and re-check the Actions tab.

## Failure triage

If validation fails:

1. Capture the failing command or GitHub Actions job log.
2. Fix import paths first.
3. Fix JSX syntax second.
4. Fix lint-only warnings third.
5. Re-run the full validation sequence.
